## 一键运行

需要 Docker、本机 Chrome，以及已经安装的项目依赖：在 `service` 执行 `uv sync --frozen`，在 `vue` 执行 `npm ci`。脚本适用于项目使用的 macOS/Linux/WSL 环境。

在仓库根目录运行：

```bash
service/.venv/bin/python scripts/test_day13.py
```

脚本依次执行：

1. 创建随机名称的 PostgreSQL 测试容器，数据库固定命名为 `day13_test`，使用临时内存卷和随机本机端口。
2. 执行真实 Alembic 迁移。
3. 运行全部 pytest，包括平时因未配置独立数据库而跳过的 PostgreSQL 事务/Checkpoint 专项。
4. 运行全部 Vitest 和前端生产构建。
5. 对生产前端包运行现有浏览器回归。
6. 启动隔离测试 API，执行真实全流程的三个阶段，中间重启 API 两次。
7. 无论成功或失败，都清理自己创建的 API/前端进程、数据库容器和临时索引目录。

仅复跑 PostgreSQL 专项与三个完整链路阶段：

```bash
service/.venv/bin/python scripts/test_day13.py --integration-only
```

每次产生独立的 `test-results/day13-<编号>/`，其中包括 `report.json`、各阶段日志和浏览器失败截图/trace。返回码 0 才表示验收成功，失败返回 1。日志和测试数据不提交 Git。

## 重启验证如何做到

`service/tests/day13_app.py` 使用生产 `app`、生产生命周期及后台文档索引 worker，按需创建专用测试成员和审批人。每次启动都保留原有项目、文档、任务、会话和审批记录。

浏览器请求通过 Vite 代理直接访问独立 API；没有 `page.route()` 伪造接口响应，也没有认证绕过或业务数据重置接口。

三个阶段分别是：

1. **重启前**：成员从空项目开始，通过 UI 上传文档、等待真实后台索引完成、提问、检查需求、提交审批；将项目/审批编号记录在临时测试文件中。
2. **第一次重启后**：索引仍可检索，原方案仍等待审批；审批人修改后批准；再次提交完全相同决定只返回原来的任务结果；成员看到任务加入看板。
3. **第二次重启后**：任务编号和数量仍与原审批结果一致，审批状态仍为已完成；删除文档后知识库不再允许基于它提问。

`test_approvals_postgres.py` 继续验证真实数据库在任务插入后发生异常时整体回滚，以及恢复执行后的幂等性；测试库名称仅允许 `day12_test` 或 `day13_test`。

## 故障处理约定

- 模型/检索失败：返回稳定错误码和请求编号，不把供应商异常正文或私有内容放进事件和日志。
- 并行节点失败或取消：停止未完成的异步分支，不生成不完整报告，释放本次执行名额。
- 生成中断：保留原会话，继续时复用会话编号；尚未完成的模型生成可以重新执行。
- 决定已保存后中断：保留 `processing` 与原决定，原审批人可继续；停止等待不会撤回已提交的决定。
- 执行已成功但响应丢失：同一审批人以同一决定重试返回已有结果，任务不重复。
- 流式 `final` 后前端会主动关闭读取器。端到端断言使用页面展示与后续权威查询，不依赖浏览器调试协议继续读取已关闭的流响应正文。

## 范围与限制

- 验收使用 `AI_MODE=mock` 和仅存在于测试目录的 Fake Embedding。上传、分块、Chroma、PostgreSQL、JWT、审批 Graph、Checkpoint、API 和浏览器操作使用真实实现。
- 假向量验证的是索引写入、隔离、持久化和调用链，不代表真实中文模型的语义检索效果。12 条固定评估用例的离线通过也不等于真实模型质量达标；真实模型回答/引用质量需按第 8 天文档另行评估。
- 模型异常与结构化输出校验由后端离线替身注入验证；本次不调用用户配置的在线模型，不消耗真实模型额度。
- 当前仍只支持单 API 实例；测试不扩大部署并发能力，也不引入无限重试。
- Jenkins 既有后端测试和前端构建会自动包含新增测试。完整浏览器/重启验收需要 Docker 和 Chrome，由上述脚本单独执行，不在日常部署时创建测试数据。
