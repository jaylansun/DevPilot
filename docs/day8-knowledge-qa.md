# 第 8 天：带引用的知识库问答

本文记录第 8 天的实现。第 11 天已增加流式问答、执行轨迹和断连取消，最新行为见 [流式输出说明](day11-streaming.md)。

## 页面变化

打开项目后，新增“AI 问答”标签页。上传文档并等待知识库显示“已就绪”，即可提问。每条引用可以展开，查看文件名、标题、片段编号和原文。回答和原文始终按纯文本显示，不执行 HTML、文档指令或外部链接。

页面区分演示和真实模式。无就绪文档时引导上传；模型未配置时显示配置提示；失败后保留问题，允许重试。停止等待或离开页面会取消浏览器请求，但同步向量计算或供应商端计算可能仍在收尾，不保证立即停止计费。

当前为单轮问答，历史问题不发送给模型；本页最多临时保留 20 轮，离开问答页或刷新即清空，不写入浏览器持久存储。这一阶段没有新增 Conversation 表或数据库迁移。持久会话、NDJSON 流、Tool、Agent 和审批按后续计划实现。

## 这次怎么实现

1. 后端从登录身份检查项目归属，禁止成员读取其他人的项目，审批人不能直接使用成员知识库接口。
2. 从 PostgreSQL 查询当前项目的已就绪文档，不读取失败、索引中、待删除文档的片段。
3. 用同一个本地 BGE 模型把问题向量化，在 Chroma 中同时过滤项目 ID 和就绪文档 ID，最多取 4 个片段。
4. 用余弦相似度阈值过滤弱相关结果。`RAG_MIN_SCORE=0.5` 是初始配置，不是正确率，应结合真实评估调整。
5. 没有可用片段时直接说明资料不足，不调用在线模型；有片段时将问题和片段交给模型生成带编号引用的回答。
6. 服务器校验引用编号存在且与正文标记一致，并从实际检索结果补齐文件名和原文。模型判断资料不足时，返回统一的未知提示。
7. 在发送片段给模型前、返回回答前重新检查项目和文档状态，避免已删除文档继续作为当前有效来源返回。

引用校验确保编号和原文来源真实，不等于验证每一句推理一定正确。真实模型仍可能误判文档中的恶意指令或事实，需要人工核对引用；它没有写业务数据或访问外部工具的能力。

后台索引和问答共享同一个带线程锁的索引服务；只支持一个 API 实例、一个 Uvicorn worker。问答最多同时执行一个，额外请求等待最多 1 秒后返回忙碌提示。模型请求超时 30 秒、最多重试一次；整体处理预算 65 秒，浏览器与 Nginx 等待上限 75 秒。不要把这个单实例实现直接改成多个 worker。

## 两种模型模式

默认配置：

```dotenv
AI_MODE=mock
```

这时仍使用真实 BGE 向量检索，但不调用在线模型，只展示相关片段引用，不能把它当成“AI 已经会回答”。模型第一次使用可能需要下载缓存。

真实模式需要在实际 .env 或 Jenkins 的 Secret file 中配置：

```dotenv
AI_MODE=live
MODEL_NAME=供应商提供的模型名称
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://供应商域名/v1
RAG_MIN_SCORE=0.5
```

接口须兼容 Chat Completions，并支持工具调用形式的结构化输出。通过 LangChain `ChatOpenAI` 接入，`with_structured_output` 接收 Pydantic 结构，不手写模型 JSON 解析。

真实模式会将问题、最多 4 段相关原文及其来源元数据发送给配置的模型供应商，可能产生费用。向量化仍在服务器本地进行。只填写你信任的供应商地址，不要将 .env 或密钥提交到 Git。

更新 Jenkins 的 `devpilot-env-file` 后重新构建，使新环境变量进入 API 容器。只修改本地 .env 不会自动修改 Jenkins 保存的凭据文件。没有改 Jenkinsfile，也没有替你修改真实 .env 或调用付费模型。

## 12 条固定评估

数据集：`service/tests/fixtures/rag_evaluation.json`，包含 3 份虚构业务文档、10 个有依据的问题、2 个应该拒答的问题。

在 `service` 目录执行（不访问用户项目数据库）：

```bash
uv run --locked python -m app.cli.evaluate_rag
```

此命令使用真实 BGE 和独立临时 Chroma，只评估检索命中，不调用在线模型，也不能据此宣称生成答案正确。复用本地模型缓存；Windows 上 Chroma 文件句柄可能导致临时评估目录清理延后。

显式允许发送虚构评估资料给已配置的在线模型并承担相应费用时执行：

```bash
uv run --locked python -m app.cli.evaluate_rag --live
```

真实评估检查来源、关键词和拒答情况。固定集中的 10 个有依据问题必须通过，2 个无依据问题必须拒答，否则返回非零退出码。关键词检查只做初筛，不替代人工审阅；仍需核对回答是否忠于引用。

CI 中的 12 条固定用例使用构造的输出检查引用契约，不联网；其通过率不是对真实模型质量的测量。真实质量验收应以上述实测和人工核对为准。

## 主要新增文件

- `rag_controller.py`：问答状态和单轮提问接口。
- `rag_qo.py` / `rag_vo.py`：问题、回答、引用及模型结构化输出。
- `rag_repository.py`：读取已就绪文档。
- `rag_service.py`：权限、检索、生成、引用校验、超时和失败处理。
- `rag_model_service.py`：Prompt、演示模式、真实模型适配。
- `document_index_service.py`：增加项目范围内检索，共享索引锁。
- `KnowledgeChat.vue` / `rag_api.ts`：问答页面与接口封装。
- `evaluate_rag.py`：隔离的固定评估命令。

技术依据：[LangChain ChatOpenAI](https://docs.langchain.com/oss/python/integrations/chat/openai)、[Chroma 查询和过滤](https://docs.trychroma.com/docs/querying-collections/query-and-get)。
